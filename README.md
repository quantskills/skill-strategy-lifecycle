# 策略生命周期控制：降权、退役与再激活

简体中文 | [QuantSkills 私有仓库](https://github.com/quantskills/skill-strategy-lifecycle)

> QuantSkills `skill-*` 项目：在冻结 Q8 因子、模型和策略输入后，重放策略状态机，比较持续启用、简单阈值、降权、冷却、退役和再激活规则的样本外净收益、机会成本与状态账本。

## 项目要回答什么

监控系统可以告诉我们策略健康度下降，却不一定能回答交易决策：出现预警后，是继续持有、临时降权、进入冷却、退役，还是等待条件恢复后再激活？动作是否真的改善了扣除交易成本后的样本外结果？停用期间错过了多少本来可以获得的收益？退役标签是否改变了交易路径，还是只是一项治理记录？

本项目把这些问题放进一套可重放的策略状态机。状态转换只使用当时已经成熟的数据，先确定当期状态和暴露，再计算后续收益；不能根据未来收益事后挑选应当停用的月份。

Q8 负责因子、模型和模型重训；E6 读取冻结的 Q8 输入，研究完整策略生命周期。E6 不重新训练 Q8，也不把监控建议直接当作交易结论。

## 当前研究结论

当前结果是回顾性样本中的描述性结果，使用 22 个时间周期、4 个相位账户和冻结 Q8 信号。多头累计净收益如下：

| 方案 | 累计净收益 | 平均暴露 | 最差阶段回撤 | 停用阶段占比 |
|---|---:|---:|---:|---:|
| 持续启用 | 23.65% | 100.00% | -26.82% | 0.00% |
| 简单阈值 | 16.57% | 57.95% | -24.85% | 42.05% |
| 生命周期规则 | 15.14% | 46.59% | -19.65% | 57.95% |
| 健康门槛敏感性 | 17.10% | 27.27% | -5.69% | 75.00% |

当前样本说明，生命周期规则减少了暴露和部分回撤，但没有提高累计净收益。相对持续启用，多头生命周期规则的累计差异约为 **-8.50 个百分点**。对冲表达下，持续启用为 -9.79%，生命周期规则为 -11.85%，也没有显示出稳定优势。

状态机的关键负结果是：取消退役标签没有改变暴露路径，因此不能把退役单独解释为交易增量。退役和冷却在当前主规则中使用相同的零暴露和恢复门槛，退役更接近治理标签，而不是已经被证明有效的交易动作。

因此当前交易研究决策是：保留状态账本、机会成本和监控审计；不把生命周期规则自动升级为实盘规则；在至少 52 个新增周度观测成熟后，再做独立确认。

### 结论怎样回答本项目选题

本项目对“策略降权、退役与再激活是否优于持续持有”的回答是：**在当前冻结 Q8 输入和这段回顾性样本中，没有证据表明完整生命周期规则优于持续启用。** 生命周期规则把平均暴露从 100.00% 降到 46.59%，最差阶段回撤从 -26.82% 收窄到 -19.65%，但累计净收益少 8.50 个百分点；简单阈值也没有超过持续启用。因此，当前规则更像风险暴露控制和治理审计工具，而不是已经验证的收益增强规则。

降权、冷却、退役和再激活已经在状态机中被明确建模，并在逐期账本中记录进入、退出、目标暴露和原因。可是本期消融显示，删除“退役”标签并没有改变暴露路径，说明退役在当前参数下主要是治理状态，尚未证明有独立交易增量。再激活承担的是恢复半仓、观察后回到满仓的路径控制；它减少了重新开仓的突变，但在样本较短时也可能带来恢复延迟和机会成本。

所以本期可执行的研究决策是：保留点时状态机和机会成本核算，继续纸面验证降权与恢复门槛；暂不把退役或再激活自动接入实盘下单；新增至少 52 个成熟周度观测，并使用独立确认期检验收益、回撤、机会成本和状态频率是否稳定。负结果本身的价值在于，它阻止了“预警后立即停用必然更好”的未经验证假设进入交易流程。

## 与 `skill-factor-drift-closure` 的联系和区别

两个项目都以 Q8 的冻结因子、模型和成熟风险统计为上游输入，都要求点时可见、扣除交易成本、保留状态或动作账本，并且都把“监控预警”与“交易决策价值”分开。它们可以串成一条链：`skill-factor-drift-closure` 先评估因子漂移后的重训、换信号或预警后降权，本项目再把已经选定的策略暴露交给生命周期状态机，继续评估冷却、退役和再激活。

| 对比维度 | `skill-factor-drift-closure` | 本项目 `skill-strategy-lifecycle` |
|---|---|---|
| 核心问题 | 漂移预警后，重训、换信号或降权能否带来样本外增量 | 策略出现健康告警后，何时降权、冷却、退役以及何时恢复 |
| 研究对象 | 因子/预测信号和告警后的处置动作 | 策略的连续状态、目标暴露和生命周期路径 |
| 主要对照 | 不处理、固定降权、预警后降权、重训、换信号 | 持续启用、简单阈值、生命周期规则及冷却/退役/恢复消融 |
| 上游模型 | 可在点时成熟边界内评估重训或换信号 | 读取 Q8 冻结结果，不重训、不改写 Q8 模型 |
| 关键输出 | 动作后的净收益、误报成本、恢复延迟和闭环统计 | 净收益、停用机会成本、逐期状态账本、状态转换和暴露路径 |
| 当前结论 | 历史样本中动态动作未被证明稳定优于冻结基线 | 生命周期规则降低暴露和部分回撤，但未优于持续启用；退役暂无独立交易增量 |

因此两者不是重复项目：前者回答“漂移发生后选哪种处置动作”，后者回答“策略进入处置后如何完整地进入、停留、退出和恢复”。前者的“预警后降权”可以作为本项目的降权触发输入；本项目的状态账本和机会成本也可以反过来为前者提供长期生命周期约束。两者都不能把回顾性结果当作未来收益保证，也不能用未来收益倒推历史停用月份。

## 适用场景

本 Skill 适用于：

- 因子或策略健康指标恶化后的降权和冷却评估；
- 策略退役、恢复和再激活规则的样本外比较；
- 需要量化停用机会成本和避免损失的研究；
- 检查状态转换是否使用了未来信息；
- 需要逐期账本、状态转换原因和输入输出散列的研究复现；
- Q8 与 E6 分工明确的多项目协作。

它不适用于未经冻结的参数优化、实时下单授权、券商成交保证、未来收益预测或替代 Q8 的因子和模型训练。

## 状态机规则

| 状态 | 目标暴露 | 进入与恢复 |
|---|---:|---|
| 满仓 | 100% | 正常状态；首次成熟 IC 告警后进入降权 |
| 降权 | 50% | 告警解除可恢复；连续告警或严重告警进入冷却 |
| 冷却 | 0% | 持续告警达到退役条件后标记退役 |
| 退役 | 0% | 连续健康观察达到恢复门槛后进入再激活 |
| 再激活 | 50% | 保留半仓观察；新告警回到冷却，无告警后恢复满仓 |

主规则只使用成熟 IC 告警，健康门槛只作为敏感性方案。监控缺失时保持原状态并清零连续健康计数，不能把缺失当作健康。重复或乱序的决策日期会被拒绝。

在决策日 `t`，只使用不晚于 `t-5` 个周度观测的成熟标签构造滚动 IC。状态转换完成后才计入未来收益。账本记录状态前后、暴露、成熟截止日、告警、连续计数、转换原因、成本、满仓反事实收益和机会成本。

机会成本定义为：

```text
停用机会成本 = 持续启用净收益 - 实际生命周期净收益
```

逐期机会成本可以拆成错过收益和避免损失，但状态归因是逐期算术累加，不能直接当作终值差或机制因果证明。

## 统计与扩展验证

主比较包括持续启用、简单阈值和生命周期规则；另报告健康门槛敏感性。统计验证使用：

- 22 个时间周期作为主要抽样单位；
- 4 个相位账户共同配对；
- 零中心循环区块检验；
- 95% 描述区间；
- BH 多重比较调整；
- 共同最大统计量单侧检验；
- 区块长度 2、4、6 的敏感性；
- 87 个非零循环位移时点对照；
- 27 组冷却、退役和恢复参数组合；
- 4 项状态规则消融；
- 缺失收益和交易成本压力测试；
- 起始状态敏感性和第二冻结信号复核。

扩展实验全部是回顾性分析，不根据结果挑选主规则，也不把同源第二信号当作独立确认集。

## 在 EVO 中运行的方法

EVO 运行时应使用**项目版本入口**，不要把压缩包拆成很多文件逐个上传。具体操作按 EVO 当前界面提供的仓库/项目导入入口完成，仓库地址为：

```text
https://github.com/quantskills/skill-strategy-lifecycle
```

建议按以下顺序执行：

1. 在 EVO 新建或选择一个有权限的项目，绑定本仓库的私有版本，并固定提交号或标签；记录仓库地址、提交号和运行时间。
2. 在运行环境中挂载或关联经过授权的 Q8 冻结输入。输入放在 `project/` 约定的路径下，不把私有数据、令牌或会话凭据提交到 GitHub。
3. 以仓库根目录为工作目录执行统一入口：

   ```powershell
   python project/evo_entry.py
   ```

   如果 EVO 的工作目录已经是 `project/`，则执行 `python evo_entry.py`，两者调用的是同一个入口。
4. 入口先校验 `project/frozen_inputs.json` 的输入指纹，再调用 `run_all.py` 完成测试、生命周期重放、统计验证、扩展验证、验收和中文报告生成。输入缺失或指纹不一致时应让任务失败，不能用本地旧结果代替。
5. 任务结束后，在 EVO 任务记录中保存平台运行编号、提交号、入口命令和完整控制台输出；同时核对仓库内 `project/runs/evo/input.json`、`project/runs/evo/output.json` 以及 `project/results/` 的文件清单和 SHA256。
6. 只有当 EVO 页面显示成功、入口返回码为 0、`output.json` 为 `succeeded`，且 `summary.csv`、`state_ledger.csv`、`opportunity_cost.json`、`report.html` 和 `acceptance.json` 均存在时，才可把这次结果写入平台证据。报告中必须区分“EVO 实际回执”和“历史项目侧结果”。

EVO 的真实回执至少应包含：平台运行编号、项目版本、输入清单及指纹、原始输出、结果文件清单、结果散列和成功状态。仅上传或下载一个 HTML/CSV 文件，不能证明研究已经从 EVO 真实入口运行。当前仓库没有把未完成的 EVO 回执写成成功记录；在获得真实回执前，本 README 中的数值只能称为项目侧回顾性结果。

## 研究限制

研究使用已查看的历史样本，不能称为未见确认集。22 个主要周期较少，区块检验依赖弱平稳假设；不显著不代表等效或无效。历史市场状态标签是冻结 Q8 代理，不能替代实时 Pandadata 证据。状态账本证明了规则可重放和点时约束，不能证明未来收益或真实成交。

本项目仅供量化研究和教育使用，不构成投资建议、交易授权或收益承诺。
