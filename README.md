# 策略生命周期控制：降权、退役与再激活

简体中文 | [QuantSkills 私有仓库](https://github.com/quantskills/skill-strategy-lifecycle)

> QuantSkills `skill-*` 项目：在冻结 Q8 因子、模型和策略输入后，重放策略状态机，比较持续启用、简单阈值、降权、冷却、退役和再激活规则的样本外净收益、机会成本与状态账本。

[![QuantSkills](https://img.shields.io/badge/QuantSkills-skill--strategy--lifecycle-5b6ee1)](https://github.com/quantskills/skill-strategy-lifecycle)

## 项目要回答什么

监控系统可以告诉我们策略健康度下降，却不一定能回答交易决策：出现预警后，是继续持有、临时降权、进入冷却、退役，还是等待条件恢复后再激活？动作是否真的改善了扣除交易成本后的样本外结果？停用期间错过了多少本来可以获得的收益？退役标签是否改变了交易路径，还是只是一项治理记录？

本项目把这些问题放进一套可重放的策略状态机。状态转换只使用当时已经成熟的数据，先确定当期状态和暴露，再计算后续收益；不能根据未来收益事后挑选应当停用的月份。

Q8 负责因子、模型和模型重训；E6 读取冻结的 Q8 输入，研究完整策略生命周期。E6 不重新训练 Q8，也不把监控建议直接当作交易结论。

## 当前研究结论

当前结果是回顾性样本中的描述性结果，使用 22 个时间周期、4 个相位账户和冻结 Q8 信号。多头累计净收益如下：

| 方案 | 累计净收益 | 平均暴露 | 最差阶段回撤 | 停用阶段占比 |
|---|---:|---:|---:|---:|
| 持续启用 | 23.65% | 100.00% | -26.82% | 0.00% |
| 简单阈值 | 16.57% | 57.95% | -24.85% | 42.05% |
| 生命周期规则 | 15.14% | 46.59% | -19.65% | 57.95% |
| 健康门槛敏感性 | 17.10% | 27.27% | -5.69% | 75.00% |

当前样本说明，生命周期规则减少了暴露和部分回撤，但没有提高累计净收益。相对持续启用，多头生命周期规则的累计差异约为 **-8.50 个百分点**。对冲表达下，持续启用为 -9.79%，生命周期规则为 -11.85%，也没有显示出稳定优势。

状态机的关键负结果是：取消退役标签没有改变暴露路径，因此不能把退役单独解释为交易增量。退役和冷却在当前主规则中使用相同的零暴露和恢复门槛，退役更接近治理标签，而不是已经被证明有效的交易动作。

因此当前交易研究决策是：保留状态账本、机会成本和监控审计；不把生命周期规则自动升级为实盘规则；在至少 52 个新增周度观测成熟后，再做独立确认。

## 适用场景

本 Skill 适用于：

- 因子或策略健康指标恶化后的降权和冷却评估；
- 策略退役、恢复和再激活规则的样本外比较；
- 需要量化停用机会成本和避免损失的研究；
- 检查状态转换是否使用了未来信息；
- 需要逐期账本、状态转换原因和输入输出散列的研究复现；
- Q8 与 E6 分工明确的多项目协作。

它不适用于未经冻结的参数优化、实时下单授权、券商成交保证、未来收益预测或替代 Q8 的因子和模型训练。

## 状态机规则

| 状态 | 目标暴露 | 进入与恢复 |
|---|---:|---|
| 满仓 | 100% | 正常状态；首次成熟 IC 告警后进入降权 |
| 降权 | 50% | 告警解除可恢复；连续告警或严重告警进入冷却 |
| 冷却 | 0% | 持续告警达到退役条件后标记退役 |
| 退役 | 0% | 连续健康观察达到恢复门槛后进入再激活 |
| 再激活 | 50% | 保留半仓观察；新告警回到冷却，无告警后恢复满仓 |

主规则只使用成熟 IC 告警，健康门槛只作为敏感性方案。监控缺失时保持原状态并清零连续健康计数，不能把缺失当作健康。重复或乱序的决策日期会被拒绝。

在决策日 `t`，只使用不晚于 `t-5` 个周度观测的成熟标签构造滚动 IC。状态转换完成后才计入未来收益。账本记录状态前后、暴露、成熟截止日、告警、连续计数、转换原因、成本、满仓反事实收益和机会成本。

机会成本定义为：

```text
停用机会成本 = 持续启用净收益 - 实际生命周期净收益
```

逐期机会成本可以拆成错过收益和避免损失，但状态归因是逐期算术累加，不能直接当作终值差或机制因果证明。

## 统计与扩展验证

主比较包括持续启用、简单阈值和生命周期规则；另报告健康门槛敏感性。统计验证使用：

- 22 个时间周期作为主要抽样单位；
- 4 个相位账户共同配对；
- 零中心循环区块检验；
- 95% 描述区间；
- BH 多重比较调整；
- 共同最大统计量单侧检验；
- 区块长度 2、4、6 的敏感性；
- 87 个非零循环位移时点对照；
- 27 组冷却、退役和恢复参数组合；
- 4 项状态规则消融；
- 缺失收益和交易成本压力测试；
- 起始状态敏感性和第二冻结信号复核。

扩展实验全部是回顾性分析，不根据结果挑选主规则，也不把同源第二信号当作独立确认集。

## 运行入口

项目级运行入口是：

```text
python evo_entry.py
```

它依次执行测试、研究主流程、行情与策略诊断、扩展验证、独立验收和中文 HTML 生成。平台级运行时应保存项目版本、平台运行编号、入口命令、原始控制台输出、输入指纹、输出清单和结果散列。

本项目已经按 EVO 项目级运行方式设计，但当前仓库记录的是项目侧入口和兼容性准备；EVO 真实任务回执尚未完成，不能把本地结果写成 EVO 平台结果。

## 输出文件

运行后主要输出包括：

- `results/summary.csv`：持续启用、简单阈值、生命周期规则和敏感性方案的净收益、暴露、回撤与成本；
- `results/state_ledger.csv`：逐期状态、暴露、转换原因、告警和收益账本；
- `results/state_transitions.csv`：状态转换明细；
- `results/opportunity_cost.json`：停用机会成本汇总；
- `results/episode_attribution.csv`：停用阶段归因；
- `results/inference_v2.json`、`results/block_sensitivity.csv`：统计推断和区块敏感性；
- `results/parameter_sensitivity.csv`、`results/ablation.csv`：参数和机制消融；
- `results/execution_stress.csv`：缺失收益与成本压力；
- `results/report.html`、`results/report.md`：中文研究报告和网页展示；
- `runs/evo/input.json`、`runs/evo/output.json`：入口输入和输出回执；
- `results/acceptance.json`：项目侧验收结果。

## 研究限制

研究使用已查看的历史样本，不能称为未见确认集。22 个主要周期较少，区块检验依赖弱平稳假设；不显著不代表等效或无效。历史市场状态标签是冻结 Q8 代理，不能替代实时 Pandadata 证据。状态账本证明了规则可重放和点时约束，不能证明未来收益或真实成交。

本项目仅供量化研究和教育使用，不构成投资建议、交易授权或收益承诺。
